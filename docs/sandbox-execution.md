# 会话沙箱执行与结果展示

## 目标与范围

模型使用 `bash` 在当前会话的非特权沙箱内执行命令，使用 `show_execution` 选择性展示真实执行记录。删除模型可见的 `run_python`；历史消息的 execution 卡片继续可读。文件交付仍使用 `output/`，不能因拆分展示工具而丢失产物发布。

本次只在本地修改、编译、审计和提交，不包含服务器部署。编译通过不能证明 Linux Docker 下的资源隔离、语言运行环境或网络策略已经通过运行验收。

安全工作区文件打开仅实现 Linux 版本，使用非阻塞/no-follow 打开后验证普通文件 descriptor，再进行读写或截断，拒绝模型制造的 FIFO、设备等特殊文件；其他平台此操作明确拒绝，不用不安全兼容分支。聊天与会话/消息删除共享 PostgreSQL advisory lease，锁使用独立连接，不长期占用业务连接池；这同时增加了每个活跃会话所需的数据库连接容量。

## 工具契约

- `bash`：参数 `command`、`cwd`（默认 `/work`）、`timeout_seconds`（默认 60，最大 300）。模型不能指定容器、运行身份、挂载、资源限额或网络策略。
- `source_paths` 可选，最多 5 个工作区源文件；执行前安全读取快照。默认只保存实际命令，不猜测任意 Bash 会执行的所有文件。
- `bash` 返回 `execution_id`、真实状态、退出码、stdout、stderr、耗时和输出截断标记；默认不发送详细代码卡片。
- `show_execution`：引用当前会话的 `execution_id`，选择展示命令/源代码、stdout、stderr；不可传入伪造的代码运行结果。显示的状态始终来自真实记录，即使隐藏 stderr 也不能将失败显示为成功。
- 源文件如需展示，必须在运行前记录快照，不读取运行后被修改的文件冒充原始执行代码。
- 执行记录不保存在 Bash 可写目录；跨会话引用必须拒绝。

## 生命周期与安全边界

每会话串行执行。每次 Bash 是新进程，环境变量和当前目录不跨调用保留，文件保留。不提供后台服务、外部端口或交互式终端。正常结束、取消、超时均须回收派生进程；仅取消 Docker exec HTTP 请求不能视为已经终止程序。

任务失败不删除工作区，不自动重试命令。优先复用容器，异常退出后恢复运行环境；内存变量和未落盘数据不保证恢复。空闲回收仅释放运行环境，不删除工作区代码。

`input/` 在容器内只读；根文件系统只读；命令以 uid/gid 1000 执行；不挂载应用数据、密钥、Docker socket。仅可信 broker 控制 Docker。网络策略需阻断内网、元数据与宿主，覆盖 IPv4 和 IPv6。

允许公网下载也意味着命令可能向公网发送文件内容；沙箱不是数据防泄漏机制。IPv6 禁用及出站 DROP 初始化必须成功；IPv4 拒绝非公网地址，并阻断可信宿主接口/路由探测出的地址和当前部署两台后端公网地址。扩容或改变敏感服务公网地址时必须同步网络保护配置并重新验收，而非仅更改 Nginx upstream。

## 资源边界与部署前置

工作区使用宿主已配置的 XFS project quota，每个会话设置 512MiB 块硬上限和 32768 inode 硬上限。可信 broker 设置并复查配额；文件系统不支持、配额未启用或权限不足时拒绝执行，不降级为扫描目录。不得为此给模型运行的 worker 提供特权模式。

人工前置检查脚本是 `deploy/prepare-sandbox-storage.sh`，本次未执行。它要求 Linux 5.14+、已在 `/var/lib/chat-lite/table-sandbox` 专门挂载并启用 `prjquota` 的 XFS、`findmnt` 和 `xfsprogs`；不自动挂载、格式化或创建 loop。脚本会创建/规范化 `jobs`、`sessions` 目录的 root 权限，并输出 quota 状态；实际准入仍由 broker 检查内核 enforcement。project ID 的 1000000..1999999999 范围需专门保留给 broker。可信 broker 增加 `SYS_ADMIN` 以设置配额，worker 不具备此能力。

旧非空且未分配配额的会话目录会被拒绝，而不是自动归档、改属或删除。上线前必须备份并离线迁移旧工作区到已配额的新目录；不得直接清空目录或对已有设备运行 `mkfs`。原有服务正常启动不等于这些前置条件已经满足。

每条命令结束后，可信 broker 停止并确认原容器已停止，再启动同一容器，从而清理所有派生进程。清场和恢复使用独立有界 context；未确认清场的会话不能执行下一条命令。内存与磁盘文件是两种状态：stop/start 不保留进程内存，持久工作文件不删除。

代码配置为内存 512MiB、CPU 1 核、PID 64、stdout/stderr 合计 64KiB；每节点最多同时执行 2 个任务、最多 4 个任务等待。普通可写临时目录与缓存纳入受配额工作区，input 单独只读挂载。`/dev/shm` 另限 1MiB，计入同一内存 cgroup；并非额外的无界临时磁盘。二进制输出中的非法 UTF-8 和 NUL 会转为可显示文本，并标记发生转换/截断；返回的是文本结果，不是无损二进制传输。

## 固定双机路由

单一 Nginx 入口按规范会话 ID 固定分桶到两个单节点 upstream，禁止请求失败后切换节点。`/api/conversations/{id}/...` 从 URI 取得 ID；`/api/chat` 和 `/api/upload` 使用 `X-Conversation-ID`，后端严格检查它与 JSON/multipart 字段一致。这个头不是授权凭据，原有用户与会话权限检查继续执行。

首次发送先调用创建会话接口，再用真实 ID 发送聊天。不得让无 ID 的聊天在任意后端创建会话后立即执行，然后在下一轮才按新 ID 路由。停止、删除、工作区列表和工作区文件下载也必须落在同一个 owner。

固定分桶适用于当前固定的两台节点，不是分布式调度或故障迁移：

- owner 不可用时返回错误，不静默切到另一台空工作区；不自动重跑命令。
- 分桶算法、比例、upstream 地址或入口配置变更需要先规划工作区迁移。首次采用此路由时，旧本地工作区可能不在新 owner 上，不应未迁移就宣称无损升级。
- 有状态请求必须经过这个 Nginx；直连后端端口不能获得同样的路由保证。生产入口防火墙应限制直连访问。
- `/api/files/{attachmentId}` 仍是经鉴权的已发布附件通道；对象存储附件可由共享 DB/MinIO 的节点读取，历史本地附件不因此自动迁移。
- 用户级 `/api/events` 目前是进程内广播，不随本轮升级变成跨节点事件总线；主聊天请求自身的执行 SSE 与之不同。

会话删除同时清理执行记录、运行环境、工作区与其对象存储副本。故障后跨机透明恢复不属于本轮目标。

## 可信展示协议

执行真值保存在 `execution_records`，绑定当前用户和会话；运行前记录命令与快照，结束后保存真实结果。进程崩溃遗留的运行记录只能标为中断，不能推断成功。

`show_execution` 产生独立 SSE `execution` 事件与 `messages.execution_cards` 元数据，列表 DTO 为 `executionCards`。新卡片不使用模型正文里的 base64 标签作为可信来源。模型或历史正文即使写出旧 execution 标签，也只能显示为未验证历史内容。

卡片状态、退出码、耗时始终显示；展示开关只影响命令/快照和 stdout/stderr 投影，不修改原始记录。隐藏源码时不向前端发送源码快照。
